Identification & Cryptographic Artifacts

The physical evidence encryption leaves behind — before you know anything about which family did it.

File system indicators

Magic bytes. Every normal file type opens with a recognizable byte signature — a PDF begins with %PDF, a ZIP-based format (including .docx and .xlsx) begins with 50 4B 03 04. Encryption overwrites that header with ciphertext, so the file's true type becomes unreadable to the OS. Many families also append a footer — a family marker, a victim ID, or the RSA-wrapped key blob itself — which is often the fastest way to fingerprint a sample without full reverse engineering.

Extension strategy. Some families append an extension (invoice.docx → invoice.docx.dlock), leaving the original name and type as a clue. Others rename entirely to a random ID (a8f3e91b7c.locked), destroying that context — which pushes recovery efforts back onto MFT and USN Journal artifacts (Module 5).

Ransom notes. Detection tooling often watches for a burst of near-identical small text files appearing across many directories inside a short window. Drop locations and naming conventions are themselves fingerprints — a plain README.txt in every folder reads very differently to a triage tool than .dlock_readme.txt. DeadLock takes this further: its note, RECOVERY_CHAT.<UID>.html, is a self-contained single-page application implementing encrypted chat, a leak-site browser, and a file browser — entirely client-side, with no backend to seize.

Entropy analysis

Shannon entropy measures how unpredictable a sequence of bytes is, on a scale of 0.0 to 8.0. It's named for Claude Shannon, who defined it mathematically in 1948 as part of founding the field of information theory. The ceiling of 8.0 isn't arbitrary — a byte has 256 possible values, and log₂(256) = 8, so 8.0 bits is the theoretical maximum randomness a byte stream can carry.

Plaintext and structured formats show low-to-medium entropy because they're full of repetition — common letters, whitespace, predictable headers. Already-compressed data (ZIP, JPEG, MP3) sits higher, because compression's whole job is squeezing out redundancy. Properly encrypted data sits at the top of the scale — indistinguishable from random noise is a design goal of cryptography, not a side effect. DFIR tooling commonly flags anything sustained above ~7.8 as consistent with ciphertext, independent of which ransomware family produced it.

Using entropy this way — as a fast, family-agnostic red flag rather than a full analysis — was formally established by Lyda & Hamrock's "Using Entropy Analysis to Find Encrypted and Packed Malware" (IEEE Security & Privacy, 2007), still the field's standard reference nearly two decades later.
