DFIR Contextualization & Reporting

From live host to a report a legal team and an executive can both act on.

This module's evidence-priority ordering follows the structure in NIST's current incident-response guidance, SP 800-61 Rev. 3 (2025). For prevention and response best practices beyond this guide's scope, see the joint CISA/FBI/NSA/MS-ISAC #StopRansomware Guide.

Evidence collection priority

  1. 01

    Memory capture

    The AES session key exists in plaintext in RAM for a brief window before it is wrapped and purged. Image memory before the process exits or that region is reused — this step loses value by the minute.

  2. 02

    MFT ($MFT) analysis

    NTFS timestamps for creation, modification, and rename. A tight cluster of mass rewrite events builds a precise encryption timeline, and can recover original filenames after a full-rename strategy.

  3. 03

    USN Journal

    Finer-grained than MFT timestamps alone — reconstructs exactly which files were touched, in what order, and helps correlate against partial or intermittent encryption patterns.

  4. 04

    VSS recovery evaluation

    Check vssadmin list shadows before assuming shadow copies are gone. Deletion routines fail for mundane reasons — permissions, early termination — and a surviving shadow is a free recovery path.

  5. 05

    $LogFile & registry hives

    The NTFS transaction log supports granular timeline work. HKLM\SYSTEM and HKLM\SOFTWARE can reveal persistence, DefaultIcon-style artifacts, service tampering, and execution evidence.

Determining feasibility of decryption

Recovery without paying is possible only when the implementation itself has a flaw. Look for:

Weak or predictable PRNG seeding

A key derived from a low-entropy seed — like system time — can be brute-forced if the approximate run time is known.

Hardcoded or reused keys

The single biggest win when it happens — one recovered key can unlock every victim protected by the same static key.

Un-flushed key buffers in memory

If the purge-from-RAM step isn't actually implemented correctly, a memory capture can recover the key directly.

Implementation bugs

Nonce or IV reuse with a stream cipher, or errors in the RSA padding scheme, can undermine an otherwise sound design.

Actively maintained families — DeadLock included — shouldn't be assumed to carry these flaws. Feasibility is decided per-family from actual analysis, never assumed by default.
